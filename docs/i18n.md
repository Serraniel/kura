# Translations

kura is written in English and translated into German, French and Japanese.
Anyone can add another language.

## How it works

- Strings live in Project Fluent files: `i18n/<locale>/kura.ftl`.
- English (`i18n/en/`) is the source. Every message ID exists there first.
- Rust code and QML use the same lookup. Neither contains user-visible text.
- Community translations go through Hosted Weblate. Pull requests also work.

## Rules for code

- Never build sentences by joining strings. Use one message with variables:
  `update-count = { $count -> [one] One update is ready *[other] { $count } updates are ready }`.
- Plural and gender forms belong in the `.ftl` file, not in code.
- No text inside images or icons.
- Layouts must allow text to grow by at least 40 % (German) and must not cut
  off Japanese text. Do not set fixed widths around text.
- Dates, numbers and sizes are formatted through the locale, not by hand.
- Package names, versions and file paths are never translated.

## Rules for translators

- Keep a term in English when that is what people in your language actually
  use. Translate it when a common native word exists. "USB" stays "USB"; nobody
  says "USB-Hafen". Check the glossary below first.
- Write for someone who has never used Linux. Short sentences, no jargon.
- Avoid addressing the user directly where a neutral phrase works. Where it
  does not, use the polite form: "Sie" in German, "vous" in French,
  です/ます in Japanese.
- Changes to English text mark all translations of that message as needing
  review.
